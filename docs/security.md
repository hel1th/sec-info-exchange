# Защита и демонстрация

API требует заголовок `X-API-Key`. Reader разрешает чтение, writer — чтение
и запись. Ключи задаются API_READER_KEY/API_WRITER_KEY, должны различаться
и содержать минимум 32 байта. Значения из .env.example предназначены только для
локальной разработки. Для развёртывания используйте случайные секреты.
Ключи, тела запросов и URL с query-параметрами не записываются в access log.

RATE_LIMIT_PER_MINUTE по умолчанию 120 на ключ; до авторизации действует
удвоенный лимит на IP. Окно — одна минута, ответ 429 содержит Retry-After: 60.
Хранилище IP ограничено 4096 записями, истёкшие записи очищаются при заполнении.
При заполнении новые IP получают 429. Forwarded/X-Forwarded-For не доверяем.
Лимиты локальны процессу и сбрасываются при перезапуске; для нескольких экземпляров
потребуется общее хранилище. MAX_BODY_BYTES по умолчанию 65536, превышение — 413.

GET /healthz и /readyz публичны и исключены из лимитов API.
Readiness проверяет БД с таймаутом 2 секунды и возвращает 503 при недоступности.
Каждый ответ получает серверный X-Request-ID, nosniff и Cache-Control: no-store.

## Демо

Запустите сервисы и дождитесь сообщения о запуске сервера в логах API:

```sh
docker compose up --build -d
docker compose logs api
docker compose run --rm tools go run ./cmd/demo
```

Compose передаёт ключи из `.env` и адрес `http://api:8080` в контейнер tools.
Экспортировать переменные в терминале не нужно.

Демо создаёт одну запись со случайным MD5, проверяет CRUD, 401, 403, 409 и 429.
Запускайте на тестовом окружении с лимитом по умолчанию; после демо лимит reader
исчерпан, перед повтором дождитесь следующего окна.
